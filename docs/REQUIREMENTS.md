## 1. Hard requirements (project)

| ID | Requirement (verbatim or near-verbatim) |
|----|------------------------------------------|
| **R0** | "The only fundamental requirement: your project must meaningfully use both PayPal and AI." |
| **R1** | Build or update an application that integrates the PayPal developer platform **(using the free sandbox environment)** along with an AI tool, model, or platform of your choice. |
| **R2** | Meaningfully integrate at least one PayPal technology, API, SDK, product, or developer capability. |
| **R3** | Meaningfully incorporate AI into the experience or functionality. |
| **R4** | Demonstrate a working prototype or proof of concept. |
| **R5** | Be sufficiently documented for the judges to understand and evaluate it. |
| **R6** | Comply with the Official Rules. *(Rules page not yet read — see SUBMISSION.md task "Read Official Rules".)* |
| **R7** | Projects can be individual or team; new or existing, as long as meaningful progress is made during the hackathon. |
| **R8** | "Any AI tool works, as long as PayPal integration is central to the project." Sponsor tools are optional. |

## 6. Official PayPal guidance (from the kickoff webinar)

| ID | Guidance |
|----|----------|
| **G1** | "Adding a PayPal button to an unrelated app is not going to be enough… PayPal should be central to what your project does… not bolted on at the end." |
| **G2** | Start from a real problem, then map it to PayPal capabilities. Don't pick a product first. |
| **G3** | Sandbox: use a **Business** account (merchant, receives money) and a **Personal** account (customer, pays). **Make both in the same country**; mixing countries causes currency confusion. |
| **G4** | Create a REST app (type "Merchant") linked to the correct sandbox business account. Client ID is public; **client secret is server-side only, never committed, never client-side.** |
| **G5** | Use env vars for client ID, secret and base URL so sandbox → live is a config swap, not a code change. |
| **G6** | Enable **Transaction Search** in the app's features. App setting changes take **up to 10 minutes** to apply; remember to click **Save**. |
| **G7** | Webhooks: register a public HTTPS URL per app (localhost needs a tunnel). Reply 2xx or PayPal retries **up to 25 times over 3 days** with backoff. **Verify the request came from PayPal.** Webhooks belong to one app in one environment. |
| **G8** | Access tokens expire (~3–9 h). Agents/tools hit 401 when they do; refresh. |
| **G9** | Test **unhappy paths** too (negative testing in sandbox: cancel, decline, refund…). |
| **G10** | Debug with Developer Dashboard → Event Logs (API calls, errors, webhook deliveries/resends) and Sandbox Notifications (emails that would have been sent). |
| **G11** | Install the **PayPal AI Toolkit** (`github.com/paypal/AI-Toolkit`): skill `paypal-best-practices`, commands `/paypal:setup`, `/paypal:sandbox`, `/paypal:test-accounts`, `/paypal:explain-error`, `/paypal:doctor`. Use it to check you're using recommended (not deprecated) APIs. |
| **G12** | **Agent Toolkit** (for building your own agents: OpenAI Agents SDK, LangChain, CrewAI, Vercel AI SDK, MCP) ≠ AI Toolkit (for your coding assistant). **PayPal MCP server** exposes orders, payments, refunds, invoices, subscriptions, disputes, catalog, shipment tracking, reporting (transactions, merchant insights). |
| **G13** | Postman: `postman.com/paypal` has official collections incl. agentic-commerce examples. |
| **G14** | Example code: `github.com/paypal-examples/docs-examples`. |
| **G15** | "Don't leave the demo video until the last minute." Best Demo Delivery is a real $5,000 prize. |
| **G16** | Some PayPal family brands (Braintree, Venmo, Hyperwallet, POS) may need regional availability or business whitelisting; check before you depend on them. |
| **G17** | Help: PayPal Discord (ask in public channels). |
